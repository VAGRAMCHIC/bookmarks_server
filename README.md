# bookmarks-server

Сервер синхронизации для читалки **Bookmarks**. Хранит для ваших устройств
место чтения, число страниц и названия книг, а если устройство их прислало,
то и сами файлы книг. Это личный сервер на одного человека: домашний NAS,
Raspberry Pi или VPS. Регистрации, паролей и веб-интерфейса нет: устройства
подключаются по одноразовому коду, а дальше узнаются по своему сертификату.

Контракт API: [`api/openapi.yaml`](api/openapi.yaml). Лицензия: AGPL-3.0-or-later.

## Установка

Нужен Go 1.26 или новее.

```sh
make build            # ./bookmarks-server, статический бинарник без CGO
make cross            # dist/: linux/amd64, linux/arm64, windows/amd64
sudo install bookmarks-server /usr/local/bin/
```

Или через Docker, см. ниже.

## Запуск

```sh
bookmarks-server serve --name "Дом"
```

При первом запуске сервер создаёт ключ и сертификат, печатает отпечаток и
начинает слушать HTTPS на порту 8443.

| Флаг | По умолчанию | |
|---|---|---|
| `--data DIR` | `$BOOKMARKS_DATA`, иначе `$XDG_DATA_HOME/bookmarks-server` (`~/.local/share/bookmarks-server`) | каталог данных, права 700 |
| `--listen` | `:8443` | адрес и порт |
| `--name` | имя из сертификата, при первом запуске — имя компьютера | как сервер называется в приложении |
| `--max-file-size` | `500M` | наибольший размер файла книги (`K`, `M`, `G`) |
| `--max-devices` | `$BOOKMARKS_MAX_DEVICES`, иначе `0` | сколько устройств можно сопрячь, `0` — без ограничения |

Сервер останавливается по Ctrl+C или SIGTERM и даёт текущим запросам до
10 секунд на завершение.

Другие команды:

```sh
bookmarks-server pair [--ttl 10m]   # код для подключения устройства
bookmarks-server devices            # список устройств
bookmarks-server remove DEVICE_ID   # отключить устройство
bookmarks-server fingerprint        # отпечаток сертификата сервера
```

Все они работают с тем же каталогом данных, что и `serve`, и их можно
запускать, пока сервер работает.

## Ограничение числа устройств

Число сопряжённых устройств ограничивается флагом `--max-devices` или
переменной окружения `BOOKMARKS_MAX_DEVICES` (флаг важнее). В
`docker-compose.yml` и в юните systemd это `BOOKMARKS_MAX_DEVICES=10`:
поменяйте число и перезапустите сервис (`docker compose up -d` или
`sudo systemctl daemon-reload && sudo systemctl restart bookmarks-server`).

Когда предел достигнут, `pair` не выдаёт новый код, а устройство с уже
выданным кодом получает ошибку «наибольшее разрешённое число устройств».
Код при этом не сгорает: отключите ненужное устройство и повторите
сопряжение с тем же кодом. Уменьшение предела никого не отключает, оно
только запрещает новые сопряжения.

## Сопряжение устройства

1. На сервере выполните `bookmarks-server pair`. Он покажет код вида
   `ABCD-EFGH-JKMN-PQRS`, отпечаток сертификата и адреса сервера. Код
   действует 10 минут и подходит для одного устройства; новый `pair`
   отменяет прежний код.
2. В приложении откройте **Синхронизация → Сопрячь**, введите адрес сервера
   (например, `192.168.1.10` или `nas.example.org:8443`) и код.
3. Сверьте отпечаток, который покажет приложение, с тем, что напечатал
   `pair`. Если они совпадают, соединение никто не перехватывает.

Код по сети не передаётся: устройство и сервер обмениваются только
HMAC-доказательствами, что знают его. После 10 неверных попыток код
гасится, а сопряжение с одного IP ограничено 5 попытками в минуту.

Потерянное устройство отключается командой `bookmarks-server remove ID`
(id — из `bookmarks-server devices`) или из приложения на другом устройстве.
Записи и файлы при этом остаются.

## Что хранится

```
bookmarks.db           SQLite: устройства, код сопряжения, записи о книгах
server.key, server.crt ключ и сертификат сервера
files/ab/cd/<bookId>   файлы книг
```

## Сертификат сервера менять нельзя

Устройства доверяют серверу только по отпечатку его сертификата, который
запомнили при сопряжении. Если удалить или заменить `server.key` и
`server.crt`, сервер получит новый отпечаток и **все устройства придётся
сопрягать заново**. По той же причине сертификат не нужно и нельзя
перевыпускать через Let's Encrypt: имя хоста и SAN в нём не проверяются.

## Резервное копирование

Копируйте каталог данных целиком. Чтобы копия базы была согласованной,
остановите сервер на время копирования или снимите копию базы так:

```sh
sqlite3 ~/.local/share/bookmarks-server/bookmarks.db ".backup /backup/bookmarks.db"
```

и отдельно скопируйте `server.key`, `server.crt` и каталог `files/`.

## Перенос на другую машину

1. Остановите сервер.
2. Перенесите каталог данных целиком, **вместе с `server.key`** и
   `server.crt`. Без них устройства не узнают сервер, и всех придётся
   сопрягать заново.
3. Запустите сервер на новой машине. Если у неё другой адрес, поменяйте
   адрес сервера в приложении; повторно сопрягать не нужно.

## Доступ из интернета

Чтобы синхронизироваться вне дома, пробросьте на роутере TCP-порт (например,
внешний 8443) на порт 8443 сервера: обычно это раздел «Переадресация портов»
или «Port forwarding» / «Virtual server». Если внешний адрес меняется,
заведите DDNS-имя (многие роутеры умеют это сами). В приложении укажите
`имя-или-ip:порт`.

Без сопряжения сервер отвечает только на `POST /v1/pair`, а соединение
принимается лишь с клиентским сертификатом, так что открытый порт
безопасен настолько, насколько позволяет TLS. Но если сервер нужен только
дома или через VPN, порт лучше не открывать.

## Docker

```sh
docker compose up -d --build
docker compose exec bookmarks bookmarks-server pair
docker compose logs -f
```

Данные лежат в томе `bookmarks-data` (внутри контейнера `/data`), сервер
работает от пользователя `nonroot`. `pair` в контейнере покажет внутренние
адреса Docker; в приложении указывайте адрес хоста.

## systemd

```sh
sudo install bookmarks-server /usr/local/bin/
sudo cp deploy/bookmarks-server.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now bookmarks-server
journalctl -u bookmarks-server -f
```

Сервис работает от динамического пользователя (`DynamicUser=yes`), данные
лежат в `/var/lib/bookmarks-server`. Команды запускайте от того же
пользователя:

```sh
sudo systemd-run --pty --wait --collect -p DynamicUser=yes -p User=bookmarks-server \
  -p StateDirectory=bookmarks-server -p Environment=BOOKMARKS_MAX_DEVICES=10 \
  /usr/local/bin/bookmarks-server pair --data /var/lib/bookmarks-server
```

(`devices`, `remove` и `fingerprint` — так же.)

## Разработка

```sh
make test    # go test -race ./...
make lint    # go vet и staticcheck
```

Интеграционные тесты поднимают сервер на настоящем TLS, подключаются к
нему Go-клиентами со своими самоподписанными сертификатами и сверяют каждый
ответ с `api/openapi.yaml`.
